## 2. The key in the row is the key the session proved

The relay writes the dial key from the certificate that authenticated the
session asserting the row, not from anything the client sent:

  stored daemon_key     -> dev_324fa024b6cd4a69678e2ae513ed8c3e
  A authenticated as    -> dev_324fa024b6cd4a69678e2ae513ed8c3e
  same device           -> True

Proved by mutation: substituting the request-carried key makes
a_machine_registers_itself_and_the_account_lists_it fail with
"the row carries the authenticated device's key, not something the client said".
