## 6. The wiring attempt that was reverted, and why

Wiring SessionAuth::check to the ledger was written and REVERTED (nothing
committed). It broke the normal device flow: a device pinned after boot
(`arreo devices issue --socket ...`, how every operator and every test adds one)
has no grant row, so the new gate refused it — the boot backfill only covers
devices that existed at startup. `crates/arreo-server/tests/audit.rs` caught it.

The gate cannot ship without grant-on-issue, and that is architectural: `arreo
devices issue` and the server half of `arreo pair` run in the CLI process against
the authority directly (pairing may run with no daemon), but the CLI may not
depend on `arreo-server`, where `TrustLedger` lives. So the ledger's type most
likely moves to `arreo-core` — its store layer (`SessionStore::record_trust`) is
already there, and the CLI already writes device records directly. Recorded in
the task file; the tree is back to increment 1, 431 tests.

## 8. A real bug found by the wiring: early exits delivered nothing

The first wiring gave a bare close instead of the refusal. Cause: the drain that
T-0052 added lived at the *tail* of `serve_session`, so only the normal exit
flushed; every early return (a refused handshake, a bad first frame, a read
error) wrote its Error into the duplex and dropped the channel with it. The flush
is now a wrapper around the whole session — all exit paths deliver their last
frame.

## 9. Two environment findings worth recording

- **check-targets caught the feature gate.** `mesh/ledger.rs` uses
  `crate::store::SessionStore`, which the sqlite-free build does not have, so the
  pure-Rust Windows type-check broke. The ledger module is now gated on the
  `sqlite` feature like `crate::store` itself, while the *rule* stays ungated (a
  build without a database can still answer "may this device do this").
- **A store written by this test process is not visible to a daemon it spawns
  afterwards** in the test harness: the daemon opens an empty database at the same
  path (its own read_dir shows a different inode) and bootstraps a new root key
  beside a root.key it also cannot see. The identical sequence from a shell works,
  which is why the backfill's e2e proof is a shell transcript rather than a test.
  Recorded in the test file so the next person does not spend the same hour.
