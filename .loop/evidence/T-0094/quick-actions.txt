T-0094 — Quick actions: a notification you can answer where you read it
=======================================================================

A Question notification carries a bounded action list (reply <text> ≤ 4096 bytes,
skip, kill). Reply sends text + newline through the existing send path
(per-verb trust gate + secret scan + device audit), never a keystroke replay.
`arreo notify act <pane> <action> [--text ...]` is the CLI door; the TUI answers
in place. Refusals are the pane's ("the pane has exited") or the role's
(byte-identical to the direct-send sentence). N−1 holds per T-0028.

REVIEW (independent reviewer, 0.88 confidence: "correct")
--------------------------------------------------------
Verdict: ship-with-follow-ups; no P1/P2. Four P3 notes:
F1 TUI prompt trims operator text, CLI door does not — ACCEPTED as-is: the trim is
  the panel's pre-existing convention for every prompt (send/spawn share it), so the
  reply prompt matching it is one convention, not two. The daemon's bound is on the
  bytes it receives; both doors agree on the wire contract.
F2 skip maps to Verb::Kill — FIXED: skip is now Verb::Send on both sides (daemon
  verb_of + TUI control_denial), because a dismissal writes no pane bytes and a
  Send-only grant is the honest capability. Test updated.
F3 N−1 decode test pins a flat positional wire shape the encoder never emits
  (real frames are [tag, {fields-map}]) — FIXED: deleted. The genuine N−1 (old
  daemon refuses the new variant loudly) is covered by compat.rs's v0-reader test.
F4 panel offers reply again while state lags after a reply — ACCEPTED as design:
  authority is state-derived, the engine cannot know sooner, and the direct-send
  path has the same property. Optimistic dismissal would trade one confusion
  (a second answer possible) for another (claiming answered before the pane proves
  it); the daemon's gate is the single source of truth either way.
