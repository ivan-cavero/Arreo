(i) The flag's default flipped to on
------------------------------------

`shutdown: opt_in != exit::OptIn::Off` becomes `shutdown: true`.

Result: RED, 77 passed / 3 failed.

Reading: with the default on, a plain `q` no longer quits at all — the live
panes in the T-0015 fixture open the quit confirmation instead, which is exactly
what "default off" means for this ticket. The (a) check goes red because the TUI
is still up; it asserts `quit_clean && serving && daemon_pid.is_some()`, so a
prompt holding the loop open fails it rather than passing it for the wrong
reason. (This is why the check was strengthened after the first mutation run:
the first version asserted only that the daemon still answered, and passed on a
TUI that had not exited.)

Not mutation-checked
--------------------
The remote-target refusal is asserted as a loud, distinct outcome instead of by
mutation: the slice runs `arreo-tui --remote ... --shutdown-on-exit`,
`--machine ... --config <exit_kills_daemon = true>`, and `--yes` alone without a
pty, and requires exit code 2 plus the refusal's own text (captured in
`20-refusals.txt`). A mutation there would be "the refusal is deleted", which is
the same check read from the other side — there is no second code path it could
silently fall through to, because the refusal happens before the terminal is
taken.
