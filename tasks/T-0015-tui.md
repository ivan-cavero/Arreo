## Goal

The TUI clients deserve: sidebar of agents (state dots + RAM bars), pane wall, mouse-first
split borders (Herdr's proven UX), themed with the engine from T-0016.

## Acceptance criteria

- [x] Sidebar: panes grouped by state with dots + pulse for question; RAM per agent.
      Groups render in attention order (`question < blocked < working < done < idle`); the
      question group carries `◉` + bold + terminal slow-blink, and every pane row shows
      `RAM bar` + a human reading (`3M`, `512K`, `—` when the sampler has no reading yet).
      Evidence: `.loop/evidence/T-0015/01-overview.txt`.
- [x] Split/resize/focus with mouse; keyboard equivalent for everything.
      Mouse: click a sidebar row or a wall tile to focus it; drag the sidebar border to
      resize the split (clamped 18–60 cols). Keys: `j/k`+arrows move, `Enter` attach,
      `Tab` cycle, `w` wall ↔ focus, `[`/`]` resize, `PgUp/PgDn/Home/End` + wheel scrollback,
      `/` search (`Enter` apply, `Esc` cancel), `q`/`Esc` quit.
      Evidence: `05-mouse-click.txt`, `07-wall.txt`, `08-border-drag.txt`, `06-resize-100x24.txt`.
- [x] Rendering: grid deltas from the daemon, no full repaints on steady state.
      Scrollback arrives as `Read { from_line }` deltas per subscribed pane (the wall
      subscribes to every pane, capped at 9); the UI draws only when an event or a poll
      arrives, and the slice asserts the idle transcript stays under 4 KiB with no
      clear-screen sequence. Evidence: `cargo xtask e2e --slice tui` ("steady state
      repaints deltas only").
- [x] **Interactive evidence (PROMPT.md §6):** scripted PTY drives the TUI with real key
      events — resize, click, scrollback search — with frame captures in
      `.loop/evidence/T-0015/`; unit tests alone do not close this task.
      `xtask e2e --slice tui` drives the real `arreo-tui` binary on a portable-pty master
      (the shipped backend): real key bytes, real SGR mouse reports, real `TIOCSWINSZ`
      resizes, screen rebuilt from the escape stream. 17 assertions, 0 failed; frames
      `01`, `03`, `04`, `04b`, `05`, `06`, `07`, `08` written with `--interactive-evidence`.

## Notes

- The TUI is a client, not an owner: panes live in the daemon (T-0005/T-0014), so the TUI
  can die and restart without touching a process tree. It never owns a PTY.
- Daemon traffic runs in its own task and reaches the UI over a channel, so a slow or
  wedged socket cannot delay a keystroke.
- `Theme` here is the minimal palette T-0016 replaces wholesale (`Theme::state_color` is
  the single seam); colors are not hard-coded in the widget code.
- Interactive driving during development also used a real tmux session; the committed
  evidence comes from the reproducible slice, not from a hand-run terminal.
